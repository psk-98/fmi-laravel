# FMI Laravel

FMI Laravel is the API and administration backend for the Face Media Index
platform. It manages users, galleries, image storage, processing jobs, face
embeddings, and gallery-scoped similarity search.

## Features

- Sanctum bearer-token authentication
- Public and private galleries with policy-based authorization
- Multi-image uploads and per-user storage quotas
- Queued image processing through the companion FastAPI service
- Multiple face embeddings per gallery image
- PostgreSQL pgvector cosine similarity search
- Image and whole-gallery reprocessing
- Filament administration panel
- Laravel Pulse monitoring
- OpenAPI documentation generated by Scramble

## Technology

- PHP 8.3 or newer
- Laravel 13
- Laravel Sanctum 4
- Laravel Octane with FrankenPHP
- Filament 5
- PostgreSQL 18 with pgvector
- Laravel database queues
- Pest 5
- Bun, Vite, and Tailwind CSS 4

## System flow

```text
FMI Web → Laravel API → PostgreSQL + pgvector
                     → database queue → FastAPI image processor
                                      → face embeddings/results
```

When images are uploaded, Laravel stores their records and dispatches one
`ProcessGalleryImage` job per image. A queue worker sends the image to the FMI
Image Processor. Laravel stores the returned face embeddings and uses pgvector
for similarity searches limited to the selected gallery.

## Local setup

Create the environment file and install dependencies:

```sh
git clone <repository-url> fmi-laravel
cd fmi-laravel
cp .env.example .env
composer install
bun install --frozen-lockfile
php artisan key:generate
```

Start PostgreSQL with pgvector and run the migrations:

```sh
docker compose up -d db
php artisan migrate
php artisan storage:link
```

The provided Compose file starts only PostgreSQL. Laravel, its queue worker, and
the image processor run separately during local development.

## Important environment variables

The database defaults in `.env.example` match the included PostgreSQL service:

```dotenv
APP_URL=http://localhost:8000

DB_CONNECTION=pgsql
DB_HOST=127.0.0.1
DB_PORT=6543
DB_DATABASE=fmi-db
DB_USERNAME=postgres
DB_PASSWORD=changethis

QUEUE_CONNECTION=database
```

Configure the image processor with values shared by the FastAPI service:

```dotenv
IMAGE_PROCESSOR_URL=http://127.0.0.1:8001
IMAGE_PROCESSOR_API_TOKEN=change-me
IMAGE_PROCESSOR_CALLBACK_TOKEN=
IMAGE_PROCESSOR_DISK=public
IMAGE_PROCESSOR_MODEL=opencv-sface-2021dec-v1
IMAGE_PROCESSOR_EMBEDDING_DIMENSIONS=128
IMAGE_PROCESSOR_MAX_FACES=20
IMAGE_PROCESSOR_TIMEOUT=45
```

The embedding dimension must match the vector returned by the processor and the
database column. Do not change it in only one service.

## Running the application

The Laravel development command starts the configured development processes:

```sh
composer run dev
```

To run Octane with FrankenPHP directly:

```sh
php artisan octane:start --server=frankenphp --watch
```

The API is available at <http://localhost:8000/api/v1>.

Image processing requires a queue worker in a separate terminal:

```sh
php artisan queue:work --tries=3 --timeout=60
```

Also start the companion FMI Image Processor on the URL configured by
`IMAGE_PROCESSOR_URL`.

## API and administration

- API base: <http://localhost:8000/api/v1>
- OpenAPI interface: <http://localhost:8000/docs/api>
- OpenAPI JSON: <http://localhost:8000/docs/api.json>
- Filament administration: <http://localhost:8000/admin>
- Pulse monitoring: <http://localhost:8000/pulse>

Authentication endpoints are public. Gallery creation, uploads, deletion,
reprocessing, owned resources, and similarity search require a Sanctum bearer
token:

```http
Authorization: Bearer <token>
Accept: application/json
```

The processor callback uses its separately configured callback token and should
not be exposed to browser clients.

## Storage

Uploaded files use the disk configured by `IMAGE_PROCESSOR_DISK`. When using the
`public` disk locally, ensure `php artisan storage:link` has been run. User
storage usage and quota values are tracked by the backend, and uploads are
rejected once a user reaches their quota until files or galleries are deleted.

## Production notes

- Run a persistent queue worker under a process supervisor.
- Use production values for all tokens, database credentials, and `APP_KEY`.
- Set `APP_DEBUG=false` and serve the application over HTTPS.
- Use shared cache and queue infrastructure when running multiple application
  instances.
- Restart Octane workers after deploying new application code.
